# 实验总表说明（A 维护）

机器可读总表：`../data/experiment_master.csv`（26 行）与 `experiment_master.json`（含字段定义、
状态枚举与更新规则）。本文件说明字段语义与维护方式。

## 1. 为什么要有这张表

- 每个实验在**运行之前**就登记：它回答哪个研究问题（RQ1/RQ2/RQ3/基准/参照/推广）、
  **唯一改变的因素**是什么、用什么数据、产出放哪。防"跑了但说不清为什么跑"；
- 状态驱动排期：`blocked_waiting` 的行就是当前的卡点清单；
- Day11（2026-11-27 晚）冻结后，本表与 C 的冻结表共同构成报告取数的唯一来源。

## 2. 字段语义

| 字段 | 含义 |
|---|---|
| `exp_id` | 实验编号，全局唯一；`{run}` 占位表示"对每个训练 run 各做一次"（配对诊断） |
| `rq` | 回答的问题类别：RQ1（改进对真实缺陷是否有用）/ RQ2（区分规则还是编辑痕迹）/ RQ3（样本还是损失）/ 基准 / 参照 / 推广 / 协议 / 历史 |
| `question` | 该实验具体回答的问题（一句话） |
| `single_varying_factor` | **唯一改变的因素**——消融与对照实验的合法性所在；"—（基线/参照）"表示不参与变化 |
| `category` / `owner` | 类别与负责人（B/C/D/E） |
| `initialization` | 起始权重；**同类别内所有对照组必须同起点**（SB 各组同起点；PP 两组同起点，与 SB 组各自独立；候选：官方初始化或已核验的旧 20k 检查点，E 于 Day3 前核实来源） |
| `data_version` | 数据版本：LOCO 官方 + B 清单版本 + D pair v2.1（注明用途子集） |
| `steps` | 训练步数；当前为"待 Day3 锁定"（候选 3k–5k 步/组或 20k，由 E 实测耗时、A 确认机时后统一回填） |
| `status` | 见下方枚举 |
| `depends_on` | 前置依赖（数据/分数/审核/检查） |
| `result_location` | 结果位置（运行目录/逐图 CSV/运行 JSON）；完成后必须回填 |
| `output` | 产出内容 |

## 3. 状态枚举

| 状态 | 含义 |
|---|---|
| `done_verified` | 有逐图分数与运行记录，C 复算通过，数字可进"已核验"表 |
| `report_level_pending_csv` | 只有报告级数字；逐图 CSV 到手并经 C 复算前不得进正式比较表 |
| `in_progress_ready` | 输入条件已具备，等待执行 |
| `pending` | 按计划执行 |
| `blocked_waiting` | 等待依赖交付（当前卡点：B 三类清单、E 逐图分数、B 样本审核） |
| `conditional` | 核心任务完成后有余力再启动（第三类别、独立 EfficientAD、RGB 光度诊断） |
| `descriptive_only` | 仅描述性参考，不进正式比较（旧 20k 运行） |

## 4. 实验分组速览（详细见 CSV）

- **BASE-***（6 行）：五类 PatchCore 基线（SB 已完成核验，PP 就绪，BB/JB/SC 等 B 清单）；
  SALAD 作者权重参照（SB 报告级待逐图 CSV，PP 待跑，其余三类条件做）；
  独立 EfficientAD（选做）；旧 20k（描述性）。
- **ABL-SB-***（4 行）：核心消融——原版 / 只空间一致性 / 只排序 / 两者都加。
  注意：本轮"只加一致性"先做**空间**路径；光照路径依赖可运行组件预测器，
  未验证则如实写"光照一致性未验证"。
- **RCT-SB-***（3 行）：排序控制 R0/R1/R2——R1/R2 消费 D 固定的同一批 70 条违规样本，
  配置只差排序开关；三组关闭一致性。
- **XCAT-***（4 行）：跨类别验证——PP 原版 vs 联合改进；BB（优先）条件扩展，
  定类前须用正常训练材料核查可构造性，不按测试分数挑类别。
- **DEV-SELECT**（1 行）：development 对上选定 margin m 与诊断阈值（不触碰 FD 对）。
- **DIAG-***（4 行）：配对诊断——SB（重摆 vs 缺件/规格错）、PP（格内 vs 跨格，总数不变）、
  PP 计数基线（应无法区分 A 对两侧）、RGB 光度诊断（条件）。

## 5. 维护规则

1. 状态变更须同步回填 `result_location`；E 每个训练 run 完成即填运行目录与逐图 CSV 位置；
2. `report_level_pending_csv` 只有 C 按逐图 CSV 复算通过后才可升级为 `done_verified`；
3. 步数在 Day3 锁定后**统一回填所有行**（同类别内同步数是"同预算"的硬性要求）；
4. 新增实验必须先登记（含问题与唯一变化因素）再运行——包括条件扩展启用的那一刻；
5. 每日站会按 `blocked_waiting` 行清卡点，不让"正在跑"变成无人负责的状态。

## 6. 数量口径（供报告引用）

- 核心训练配置：SB 4 消融 + 排序控制补缺 1（R2；R0/R1 可复用消融组）+ PP 2 组 ≈ **7 组**
  （不计条件扩展与重复种子；关键对照如波动大，优先重复最不稳定的一对，而非新增研究问题）；
- 配对诊断对象：FD 用途对（SB 15 / PP 46，approved 后计分）+ 计数基线；
- 五类基础覆盖：PatchCore 与 SALAD 作者权重"尽量覆盖五类"——覆盖到哪类，结论就写到哪类。
