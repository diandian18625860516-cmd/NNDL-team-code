# 重新开始的工作顺序

2026-11-18：根据组长要求，旧 A/B/C/D/E 分工、旧冲刺日历和旧七组实验配置停止作为当前执行安排。历史材料保留在新仓库外，用于查证和选择性复用。

本次重新整理并不意味着所有旧工作无用：数据文件、作者源码、检查工具可以核验后复用；成绩必须有逐图预测和运行信息才能进入新结果表。来源不清的模型不能作为公平对照的起点。

## 新的推进顺序

1. **共同入口**：每个人拿到同一仓库，运行基础检查。已准备。
2. **数据与来源**：先核对 Screw Bag；补齐 Pushpins，再准备其余三类。登记原图、组成图、权重来源。不同组成图生成方式暂不混用。
3. **原版推理**：在一台确认可用的 NVIDIA GPU 机器，用作者权重跑 Screw Bag。保存逐图分数和模型来源。这属于作者权重复评。
4. **统一评价**：用同一套代码从逐图分数算出逻辑、结构、macro、pooled AUROC。明确分数越大是否越异常。
5. **短训练闭环**：确定数据划分、ImageNet 辅助数据设置、初始权重和预算，完成短训练、保存、恢复和推理。测量耗时、显存及费用。
6. **新的实验设计**：再决定如何检验审核样本、一致性、排序；同类别对照保持起点、样本使用范围、训练预算和评价一致，拆开因素贡献。旧七组只是历史方案，不自动执行。
7. **扩展与展示**：五类基础评价按资源推进；核心完成后考虑独立 EfficientAD、更多类别或重复运行。每个人讲清自己的代码输入、处理、输出和验证。

这些任务有前后依赖，但数据核对、评价工具和环境准备可以同时做。人员在 `TASKS.md` 重新认领，每项任务写一个负责人和一个复核人；不再按旧字母角色分配。

## 已知问题和处理办法

- 旧数据用途表与旧生成样本有冲突：新的训练/开发/最终诊断清单确定前，旧编辑样本保持候选状态。
- 自制组成图与作者组成图的标签语义不同：先用同一种表示跑通原版，再讨论更换表示的对照。
- 旧 PatchCore 汇总表曾缺逐图分数：重新接入时需要可核对的分数文件，而不是只抄汇总。
- 使用过诊断源图的检查点不适合声称“从未见过这些源图”。应登记训练、归一化、开发调参等使用记录。
- Mac 可以完成整理和检查；源码包含 CUDA 调用，GPU 模型运行尚未验证。

## 当前完成的准确边界

现在交付的是有版本记录、可共享的代码起点和轻量检查工具。模型环境、PatchCore 实现接入、新实验配置、改进损失及 GPU 运行都列为后续任务。课程截止日期和成员安排由小组重新确认，不沿用历史日历。
