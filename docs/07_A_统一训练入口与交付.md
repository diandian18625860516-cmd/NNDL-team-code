# A 的实际交付：统一训练入口与 Screw Bag 第一轮约定

更新：2026-11-24。协议编号：`ABC_SB_CONTINUE_V1`。

**这份包把共同条件填成了具体数值，并提供了训练程序。它不是已训练好的模型，也不是已经得到的实验成绩。**

它替代此前 `abc_screw_bag_protocol.draft.json` 中训练步数、入口和划分未确定的状态。旧草案留作历史；本轮只读取 `configs/abc_screw_bag_v1/`。这是 A 现在可以发给 B、C 的第一版共同约定，不代表他们已审核或接受所有新增目标细节。

## 1. 用普通话理解这次交付

之前只有“大家要用同样的条件”的要求。现在提供了同一张具体的实验安排表、真正执行这张表的程序，以及核对材料是否对应的方法。

- **SB0：** 从大家相同的作者权重出发，继续使用原来的训练目标和作者的组成图扰动方式。
- **SB4：** 在符合条件的采样位置换成审核过的违规组成图，仍用原来的训练目标，不增加一致性或排序要求。
- **SB2 对 SB4：** 两组看相同的图片、同一批编辑版本，主要区别只有排序目标开关，可以判断“额外排序要求”是否有用。
- **SB4 对 SB0：** 看更换一部分训练样本是否有用。
- **SB1 对 SB0：** 原有基础训练样本生成方式相同，额外用合法配对约束分数稳定。
- **SB3 对 SB2：** 在同样的审核样本条件下增加一致性目标，观察联合效果。

SB1 与 SB3 的基础样本条件不同，因此不能只凭 SB3 对 SB1 的差值声称它完全来自排序。五组不是所有因素都完全相同的二乘二设计，报告应按上面的成对比较解释。

## 3. 样本到底如何进入训练

每轮先打乱 335 张正常源图，逐张取用；全部取完再打乱。源图次序、供扰动使用的另一张源图、是否扰动及随机种子都会写入 `schedule.json`。

每步以 0.5 的概率进入组成图扰动位置，其余位置保持原样。在扰动位置：

- SB0、SB1 使用作者的四种组成图扰动函数之一。
- SB4、SB2、SB3 如果该源图有已审核的训练配对，就使用配对里的违规版与异常区域图；否则仍使用作者扰动。
- 同一源图有多组配对时按固定顺序选择；SB4、SB2、SB3 必须拿到同一份配对清单和图片文件。
- 新增目标只在这个位置有已审核配对时计算。每次运行会记录实际能用到配对的更新数，不能把 5,000 步误写成使用了 5,000 次审核样本。
- **SB4 的编辑图确实进入基础重建/异常区域损失并影响更新，不只是读一下文件而没有训练作用。**

本轮新增目标只使用组成分支，不修改 RGB 照片，也不声称已经完成 RGB 编辑或重新运行作者自动分割流程。真实照片的用途是保留原有外观分支训练与官方评价。

## 4. 新增目标的确切含义

这版把截图中的数值写进可执行配置：`margin=0.1`、开启时 `lambda_spatial=1.0`、`lambda_rank=1.0`、`photo_loss=false`。关闭的目标权重必须为 0。这些是第一轮工程设定，不是已经验证最好的参数。

这里的分数 s 是：组成异常图先经过 sigmoid，再取最大的像素值，范围为 0 到 1，越高越像异常。**它不是最后测试时多个分支融合后的分数。**

- 一致性：`(s(合法版) - s(原版))²`。让合法改变前后评分接近。这版是“组成分支图像级分数一致性”，不是逐像素特征对齐。
- 排序：`max(0, 0.1 + s(合法版) - s(违规版))`。违规分数比合法分数高至少 0.1 时不再处罚，差距不足时推动两者分开。
- 联合目标：原有五项基础损失 + 开启的一致性损失 + 开启的排序损失。

计算新增目标时临时关闭组成模型的 dropout 随机性，但**不关闭梯度**，计算完再恢复训练状态。这样比较的是图片变化，而不是两次随机丢弃神经元的差异。

若 B 已有不同的损失定义，应明确列出差异，再一起发布 V2；不要让 B、C 各用一套定义而仍标成同一个实验。正式运行前需完成此实现的短训验证，本机材料预检不等于模型已经跑通。

## 6. B 还需要交什么；A 已经交什么

A 已提供：统一程序、5,000 步预算、种子、明确源图清单、起始权重指纹，以及各组开关。

B 需要按 `templates/abc_pairs.example.json` 提供真实 JSON 和图片：

1. `source_path` 必须来自本版 335 张训练清单；开发和诊断配对另外保留，不能冒充训练对。
2. `source_map_sha256` 与作者原始组成图匹配；合法/违规版本均采用同样的 0..5 标签索引，256×256 的 P 或 L 图，不能使用重新上色的 RGB 图。
3. 合法版必须确实发生变化且符合记录的产品规则；违规版违反该规则。不能仅靠程序检查像素不同就判定规则正确。
4. 异常区域掩码为 256×256 的 L 图：0=其他区域、255=异常监督区域，至少覆盖违规版相对原版发生变化的所有标签像素；审核者核查区域语义。
5. 每个文件有真实 SHA256；记录审核人、日期、原因、规则依据，并将人工通过的记录设为 `approved`。

这个接口接受 B 的已验证材料，**没有把旧 D 的不兼容组成图转换成“作者组成图”，也没有自动替 B 审核。** 旧审核表只用于追踪，不能替代图片和清单。审核人字段为空的“approved”不能直接使用。

### 在训练机器上安装与短训（这一步会真正跑模型）

使用 Python 3.10/3.11 的独立环境，先安装依赖；如果平台已有兼容 PyTorch，可先核对版本，避免改动其他同学正在用的环境。

```bash
python -m pip install -r requirements-training.txt
python -m unittest discover -s tests -p 'test_abc*.py' -v
```

下面 `/data/...` 是训练机器示例路径，需换成真实路径：

```bash
python scripts/train_abc.py --config configs/abc_screw_bag_v1/SB0.json --rgb-root /data/mvtec_loco --maps-root /data/mvtec_loco_composition_maps --weights /data/salad_loco.zip --out outputs/ABC_V1/SB0_smoke --smoke --stop-after 50
```

完成 50 步会保存，接着从这个保存点继续到 100 步：

```bash
python scripts/train_abc.py --config configs/abc_screw_bag_v1/SB0.json --rgb-root /data/mvtec_loco --maps-root /data/mvtec_loco_composition_maps --weights /data/salad_loco.zip --out outputs/ABC_V1/SB0_smoke --smoke --resume outputs/ABC_V1/SB0_smoke/checkpoint_latest.pt
```

预期：状态 `completed`、`smoke=true`、`next_step=100`；日志损失/梯度为有限数，更新梯度非零，第二段从第 51 步开始。首次还需和另一个目录的不中断 100 步运行比较最终状态，验证恢复一致性。**代码提供了恢复机制，但完整训练依赖及 CUDA 环境尚未就绪，尚未完成这个实测，不能写成已验证。** 本机已有的 PyTorch 2.2.2 / torchvision 0.17.2 环境已通过小型张量损失/梯度测试；正式入口需使用依赖清单中的版本，不能把这些单元测试当作完整 SALAD 训练通过。

短训只用前 16 张训练源图估计教师统计量，正式使用 335 张。短训存档不能接成正式训练起点。

## 8. 跑完后会交出什么

- `resolved_protocol.json`：本次共同条件、代码/原图/配对指纹和环境版本。
- `schedule.json`：每一步抽到哪张图、用哪个随机种子。
- `steps.jsonl`：逐步损失、梯度大小、实际使用的配对、用时、学习率与 GPU 显存。
- `checkpoint_latest.pt`：完整恢复用存档，包含模型、优化器、调度器和教师统计量。
- `status.json`：运行中、完成、按要求暂停或失败，不能靠文件存在就宣称完成。
- `trained_models/`：成功跑到约定步数后导出的五个模型；附 `TRAINING_PROVENANCE.json` 区分短训和正式追加训练。

**训练完成仍不等于评价完成。** 本入口还没有自动产出官方测试逐图分数和 AUROC，C 的推理入口必须加载这些新权重并标记为 `continued_training`，不能沿用作者权重标签。

后续评价要按相同口径输出：341 张官方测试的逐图分数、逻辑/结构 AUROC、二者 macro、类别内 pooled；诊断配对另表记录合法与原版分数差、违规高于合法的比例与分数差。分数越高越异常。跨五类汇总时平均各类别指标，不把混在一起的所有图片称为“五类等权平均”。

教师统计和 Mahalanobis 参考特征只使用本轮 335 张训练源图；分数校准使用固定 60 张 validation；不从测试/最终诊断图拟合归一化、调参或选最佳模型。官方融合算法沿用已有复评代码，需由 C 按这些源图清单接入。五组统一评价最后一步模型；开发集调参必须记录，最终诊断与测试在方案固定后使用。
